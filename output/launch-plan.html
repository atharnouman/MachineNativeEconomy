Launch plan Drafted 11 Oct 2026 Working name apgw → SpendMarshal Apache-2.0

The neutral control plane for agent payments.

One self-hosted service between an organisation's AI agents and any payment rail. Agents hold shrink-only credentials, never keys. Every payment passes policy, is capped on-chain, and leaves a signed receipt an auditor can verify offline. The gateway never holds funds.

Message pillars

Enforcement below the model

Agents carry credentials that can only shrink. Caps, payees and expiry are enforced on-chain, so a prompt injection cannot spend what the policy never allowed.

Receipts are the unit of truth

Every decision, settlement, approval and policy change is a signed, hash-chained receipt. The bundle verifies offline and anchors on-chain. Reconciliation, audit and later reputation all come from it.

Any rail, any payee, one config block

x402, MPP and Lightning today; AP2 and card tokens next. A payee accepts every governed agent with one middleware call; standard payloads mean any public facilitator can settle.

What it is not: a wallet, a facilitator, a chain, or a consumer checkout. It never holds funds or risk.

Channels and audiences

Agent builders

MCP registry, framework example repos, the launch post. They want the five-minute path from "my agent needs to buy data" to a governed payment with a receipt.

API owners

The payee middleware guide. They want paying agents without learning three rails, and to know which gateway stood behind a call.

Finance and compliance

The offline verifier and the accounting export. They want one record that explains every agent payment after the fact.

Standards and rails

Interop results in the x402, MPP, Web Bot Auth and ERC-8004 threads. Rail owners structurally cannot be the neutral layer; show them the gap filled.

Risks and the answer to each

Agent payment volume arrives later than expected

Keep costs near zero, stay open-source, let design partners pull the roadmap. The window to be the reference implementation is the next one to two years.

A rail owner ships its own policy layer

Neutrality and multi-rail are the moat they cannot copy; receipts across rails are the data they cannot see. Interoperate through standard payloads so switching is free.

A security incident with real funds

Audit before mainnet, low caps in beta, bounded operator and kill switch by design, a published disclosure policy.

One maintainer

Sequence ruthlessly, co-fund partner work, write contributor docs early, ship fewer things fully.

Name or trademark collision

Search before publishing; rename is cheap today and expensive after wave 2.
