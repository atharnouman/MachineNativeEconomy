# Threat model (Phase 1)

Scope: an organisation runs SpendMarshal so its agents can buy resources with USDC. Attackers want to move funds outside policy, consume services without paying, or falsify the record.

| # | Threat | Control | Where enforced | Test |
|---|---|---|---|---|
| 1 | Prompt injection / memory poisoning makes the agent request a bad payment | Agent never signs; gateway evaluates policy on every intent; caveats + budgets + velocity + deny rules | gateway `evaluate()` | `policy.test.ts`; demos "denies over-limit", "rate_limit", "daily budget" |
| 2 | Compromised agent framework bypasses the gateway | The framework holds only a bearer credential, not a key; nothing it can send moves funds | design | demo: credential alone cannot settle |
| 3 | Gateway host compromised (session-key secret, gateway key) | Gateway is a **bounded operator**: the owner grants it a root session; everything it delegates is inside that cap, payee allowlist and expiry; it cannot unpause | chain (ADR-0006) | `test_LineageSpendPropagatesAndRootCapBoundsSubtree`, `test_PauseBySessionKey_UnpauseOwnerOnly`; Phase 1 demo steps 3, 9, 11 |
| 4 | Sub-agent escalates its own privileges | Attenuation can only append caveats (HMAC chain); effective limit is the conjunction; `grantChildSession` re-checks subset on-chain; lineage spend charged to every ancestor | core + chain | property test (500 runs); `test_RevertWhen_ChildWiderThanParent_*`; invariants |
| 5 | Replay of a signed authorization | `nonce` single-use in `AgentAccount`; `validBefore`; MPP challenge ids single-use | chain + payee | `test_RevertWhen_Replay` |
| 6 | Free-riding: resource served without payment | Payee serves only after facilitator `/settle` success (x402) or its own on-chain settlement (MPP) | payee middleware | demo settlements have tx hashes |
| 7 | Malicious / lying facilitator or payee claims a settlement that did not happen | Gateway confirms the tx receipt contains `PaymentExecuted(intentHash, amount, to)` before committing the ledger | gateway `confirmPayment` | `pay.ts` confirm stage |
| 8 | Settlement race (double service for one payment) | One nonce per intent; payee settles synchronously before serving | chain + payee | `test_RevertWhen_Replay` |
| 9 | Payee substitutes a different payTo or asset | Gateway signs the authorization with the quoted `payTo`; chain enforces target/token allowlists; gateway rejects non-configured asset | gateway + chain | `test_RevertWhen_TargetNotAllowed` |
| 10 | Kill switch bypass | Gateway flag (one request) + on-chain `pause()` by the owner or any active **root** session key (one block); child session keys cannot pause, so a leaked sub-agent key cannot halt the account; unpause owner-only | both | `test_PauseBySessionKey_UnpauseOwnerOnly`; both demos |
| 11 | Tampered or deleted receipts | Hash chain + gateway signature; head anchored on-chain; verifier checks seq/prev/sig/anchor | core + chain | `receipt.test.ts`; `verifyBundle`; demos 11/11 |
| 12 | Policy edited silently, or a decision attributed to the wrong policy | Policy versions with `prevHash` chain and activation times; every decision cites a hash; verifier requires the version active at the receipt's time | core + gateway (ADR-0008) | `evidence.test.ts`; Phase 1 demo step 10 |
| 13 | Forged or replayed approval | Signed resolutions bind approval id, principal, intent hash, amount and verdict; verifier checks each against the key its approver held at that point in the receipt chain (ADR-0019); approvals are single-use and expire; a changed quote invalidates the approval | core + gateway (ADR-0007) | `approval.test.ts`, `evidence.test.ts`; Phase 1 demo step 7 |
| 14 | Front-running an EIP-7702 account's initialisation | `initialize` accepts only self-calls | chain | `Eip7702.t.sol`; Phase 1 demo step 2 |
| 15 | Signature for one account replayed on another (7702 shares bytecode) | EIP-712 domain binds `verifyingContract` = the account address | chain | `test_DomainSeparatorBindsToTheEoaAddress` |
| 16 | Agent burst drains a budget before anyone notices | Velocity rules (per principal/agent/credential, rolling windows) and `rate_limit` caveats; budget periods | gateway | `policy.test.ts`; Phase 1 demo steps 6, 8 |
| 17 | PII leakage in payment metadata | Rails carry only the authorization struct and intent hash; approval request bodies are never written into receipts | design | — (explicit filter + test still planned) |
| 18 | Sybil reputation | Not in scope yet; design: feedback only against settled receipts | — | v1.0 |
| 19 | Chain reorg after confirmation | Waits for inclusion only; confirmation depth per chain still planned | — | — |
| 20 | Gas griefing of the relayer | Relayer only submits authorizations that passed `simulate`; per-tx gas cap still planned | partial | — |
| 21 | The EOA key behind a 7702 account | Delegation does not restrict the EOA key itself; it remains the owner and can move everything. Keep it cold; agents only ever hold session credentials | operational | documented in SECURITY.md |
| 22 | A public facilitator (standard x402) tries to settle something the policy never allowed | The account answers ERC-1271 only for digests it pre-approved under its caveats; a paused account answers nothing; the token's nonce blocks replay | chain (ADR-0009) | `Erc3009Interop.t.sol`; Phase 1 demo step 12 |
| 23 | Standard path: pre-approval charged, settlement never happens | Funds do not move; after the authorization window `reclaimApproval` restores the charge (permissionless, checks the token's nonce state); the gateway's maintenance endpoint runs it and receipts it | chain + gateway (ADR-0015) | `test_ReclaimExpiredUnusedApproval`; Phase 1 demo "orphaned pre-approval reclaimed" |
| 33 | ERC-4337: a bundler or user operation tries to widen what a session key can do | `validateUserOp` accepts only active session keys; callData runs with `msg.sender = EntryPoint`, so owner-only functions revert; caveats apply inside the permissionless entry points | chain (ADR-0015) | `Erc4337.t.sol` |
| 24 | Store corruption or partial writes | SQLite WAL with synchronous writes; receipts are canonical JSON blobs so signatures still verify after any migration; JSON driver writes whole-file | store (ADR-0010) | store tests on both drivers |
| 25 | Leaked bearer credential (logs, prompt, compromised framework) | `holder_key` caveat: requests must be RFC 9421-signed by the holder's Ed25519 key over method, authority, path and body digest; nonce window; binding can be replaced only by delegation, never removed | gateway + core (ADR-0011) | `httpsig.test.ts`, `credential.test.ts`; Phase 1 demo "stolen credential is useless" |
| 26 | Payee cannot distinguish a governed agent from a bot (and declines or rate-limits) | Outbound Web Bot Auth signatures with a signed key directory; payee middleware verifies and can require them | gateway + payee (ADR-0011) | Phase 1 demo "payee requires Web Bot Auth" |
| 27 | Forged key directory for a Signature-Agent origin | Directory responses are signed; payees cache per origin and may pin keys or restrict `allowedAgents` | payee | — (pinning is operational) |
| 28 | Metrics endpoint leaks operational detail | `/metrics` carries only aggregate counters and durations, no identifiers; expose it to the scraper network only | deployment (ADR-0012) | — |
| 29 | Payee over-charges a subscription (too often, too much, after cancellation) | Gateway enforces interval (429), per-charge and total caps (403), count, expiry and cancellation (410); every charge runs full policy and the on-chain simulate; refusals are receipted | gateway (ADR-0013) | Phase 1 demo steps "payee charges on cadence", "metered stream" |
| 30 | Stolen subscription charge token | Token is scoped to one subscription and only ever yields policy-bounded charges to the subscription's own payee address; stored hashed; cancellation kills it | gateway | — |
| 31 | Lightning: payee takes payment and does not deliver | Preimage is retained as proof; receipt records `delivered: false`; the agent sees the failure | gateway (ADR-0014) | `settleLightning` |
| 32 | Lightning spend is not bounded by the on-chain account | Policy and budgets apply at the converted amount; the Lightning wallet balance is the hard limit, keep it small; FX rate is recorded per receipt | operational (ADR-0014) | — |
| 34 | Agent uses the gateway as a proxy into the operator's network (payee URL at loopback, link-local metadata, private ranges, `file:`) | `checkOutboundUrl` at the intent boundary and again in `payeeFetch`: http(s) only, no URL credentials, loopback refused unless `outbound.allowLoopback`, private/link-local/CGNAT unless `outbound.allowPrivate`; optional `outbound.allowedHosts` pins the payees a deployment may contact | gateway (core `net.ts`, ADR-0016) | `net-and-stage.test.ts`; Phase 1 demo "gateway refuses to fetch private addresses" |
| 35 | Payee redirects the paid retry to a third host that harvests the payment headers | Redirects are never followed (`redirect: "manual"`): a 3xx ends the attempt; payment headers only ever reach the host the policy evaluated | gateway `payeeFetch` | — |
| 36 | Caller turns a payee into a proxy through a crafted `Signature-Agent` origin (SSRF via the key-directory fetch) | The origin must be http(s) with no path or query and public, unless listed in `allowedAgents` or `allowPrivateAgents` is set; pin `allowedAgents` in production | payee middleware | classifier in `net-and-stage.test.ts`; Phase 1 demo pins `allowedAgents` |
| 37 | One agent lists or cancels another agent's subscriptions with a credential of the same principal | Subscription management is scoped to the opening credential's lineage (itself and its ancestors); the admin token manages a whole principal | gateway `managesSubscription` | Phase 1 demo "subscription visibility follows the credential chain" |
| 38 | Payee floods the charge URL to grow the receipt chain (storage exhaustion) | Refusal receipts are throttled to one per subscription interval and carry the count of refusals since the last one; metrics count every refusal | gateway `charge()` | — |
| 39 | A looping or hostile agent grows the receipt chain through denied attempts (storage exhaustion) | Denial receipts are throttled per credential (50 per 10 minutes, then one receipt per window carrying the suppressed count); the request still answers 403 | gateway (ADR-0017) | `scale.test.ts` |
| 40 | A client retry after a network error pays twice | `Idempotency-Key`: same credential + same key returns the stored outcome for 24 h; concurrent duplicates share one execution; transient failures are retried | gateway `idempotency.ts` (ADR-0017) | `scale.test.ts`; Phase 1 demo "retried request pays once" |
| 41 | A slow or hostile payee holds requests, reservations and relayer slots open | Every payee request aborts after `payeeTimeoutMs`; a timed-out probe reserves nothing; concurrent intents cannot both pass an off-chain budget because the decision is re-run synchronously right before the reservation | gateway `payeeFetch`, `payInner` (ADR-0017) | Phase 1 demo "payee that never answers"; "five concurrent payments" |
| 42 | An approver key is rotated or retired: honest bundles stop verifying older approvals, or a new or removed key signs for a position it never held | Every key change is an `approver.registered` / `approver.removed` receipt in the principal's chain, written before the gateway serves and before any signed resolution; the verifier checks each resolution against the key in force at its position and requires the exported `approverHistory` to match the receipts | core `verifyBundle`, gateway `ApproverKeys` (ADR-0019) | `evidence.test.ts`, `approver-history.test.ts` |

## Non-goals in Phase 1

Custody of the owner key, fiat, KYC/KYA of counterparties, dispute resolution, legal mandate binding to a verified human identity.
